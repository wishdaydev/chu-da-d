# 普通模式（启发式）调优复盘

> 时间：2026-11-01　对象：`AIDecision.kt`（零算力的规则启发式）
> 结论先说：**四个改动方向全部实测为负收益，已全部回退。这一轮真正的产出不是更强的启发式，而是一把能分辨 2~3pp 的尺子，以及"普通模式已接近规则上限"这个可交付的判断。**

## 一、定位与基线

普通模式的价值是**零算力**（不搜索、每步毫秒级返回），用在大师模式的低配置档、以及作为大师搜索模拟人类时的行为参考。所以"优化"的前提是**不引入搜索**，只改规则与打分。

基线口径（3 大师 + 1 启发式，大师开 `w=0.8` 建模与 selfish，seed=7，100 局）：

| 节点预算 | 对应真机 | 启发式胜率 |
|---|---|---|
| 47,000 | 手机 3s | 18.0% ±8.5 |
| 60,000 | 手机 3s（中局口径） | 19.0% ±8.5 |
| 88,000 | 手机 5s | 21.0% ±8.5 |

同场 3 个大师平均每座 27.3%（34 / 28 / 20），而牌力均等时理论值是 25%。也就是说**大师对启发式的净优势只有约 9%**，远不是碾压。这既说明启发式不弱，也说明"再往上抬"的空间被对手强度封住了。

## 二、方法：先造尺子，再改代码

用"对 3 大师的胜率"当尺子是钝刀，两个硬伤：

- **分辨力不够**：100 局 95% 置信区间 ±8.5pp，而候选改动预期收益只有 2~3pp。
- **天花板太低**：已到 18%，最多还能涨 18pp 就到"必胜"，量程被压缩。

于是给 sim 加了两个开关，改成**同场对抗**（基准点 50%，量程最大）：

| 开关 | 用法 | 判据 |
|---|---|---|
| `LEGACY_SEATS=1,3` | 指定座位跑 `sim/AIDecisionV0.kt`（本轮开始前的快照），其余座位跑当前 `AIDecision` | 四家全启发式、新版坐 0/2：新版两座合计胜率 >50% 才算变强 |
| `NODE_LIMIT_SEATS=0:10000` | 按座位覆盖节点预算 | 同源不同算力对打，测"算力 → 胜率"曲线 |

关键点：**启发式不搜索，400 局只要 1 秒**。这让"多 seed、大样本"从奢侈变成默认动作。

精度：400 局 → 新版两座合计 800 个决策，标准误 1.77pp，95%CI ≈ ±3.5pp。单纯一次 400 局只能判"有没有 >3.5pp 的变化"；要判 1pp 级差异需 3 个 seed × 1200 局（7200 决策，CI ≈ ±1.2pp）。

## 三、诊断：改之前列出的缺口

| # | 问题 | 判定 |
|---|---|---|
| F1 | "下家"取错数组元素：`getOpponentCardCounts` 按座位号升序返回，而 `AIDecision` 把 `[0]` 当下家 | **真 bug** |
| F2 | 只保护下家报单，不保护其他报单者 | 待验 |
| F3 | 跟牌完全不记牌，不知道自己这手是否"绝对最大" | 待验 |
| F4 | 跟牌永远出最小可压，`cost` 被 `mainRank*2` 主导 | 待验 |
| F5 | 收官（≤4 张）无专门逻辑 | 待验 |
| F6 | 权重全是手工常数（`HAND_COST=20`、`breakPenalty 6/12`），从未扫描 | 待验 |

本轮先打了 F2、F3、F4 相关的一批，以及一个诊断时新发现的 F7（手数估算不计同花）。

## 四、实验记录（全部同场对抗，全部回退）

基准：三项全关时测得 **49.3%**（对 V0 快照）。400 局、seed=7。

| # | 改动 | 机制假设 | 实测 | 判定 |
|---|---|---|---|---|
| E1 | **夺权奖励**：跟牌压上后若"无人能再压"，减价（-40 ~ -100） | 夺回领出权 → 连续走牌 | 48.5% | **-0.8pp**，无效 |
| E2 | **报单罚扩展**：把"下家剩 1 张"的保护扩展到"任一对手剩 1 张" | 任何对手报单都该拦 | 47.3% | **-2.0pp**，有害 |
| E3 | **收线奖励**：出完这手只剩 1 手时减价 | 快速收线 | 决策从未被改变 | **0**，死代码 |
| E4 | 三项同时开 | — | 46.5% | **-2.8pp** |
| E5 | **手数估算补同花拆法**：原 `estimateHands` 只按顺子+同点数合并，完全不看同花 | 高估手数 → 出牌选择偏掉 | 3 seed × 1200 局 = **48.9%**（-1.1pp，约 1.9σ） | 无收益 |

单项差距多在 1~3pp，接近标尺 ±3.5pp 的噪声下限，所以判据不是"显著变弱"，而是：**四个方向没有任何一个显示正向，且四项同向偏负**。按"改动必须有正证据才上线"的原则，全部回退。

### 为什么这些"显然有用"的改动会失败

- **E1 夺权奖励**：4 人局里领出权极不稳定——你领出，下家用更大的牌压住就直接接走牌权。为了"抢权"打出大牌，等于用确定性的大牌去换一个大概率保不住的临时权利，净亏。
- **E2 报单罚扩展**：一旦"任意对手剩 1 张"就压单张优先级，它会在大量本无威胁的局面下拆对子、选更差的牌型。保护范围扩大 3 倍，误伤也随之扩大 3 倍。
- **E3 收线奖励**：与 `estimateHands` 的手数项同向，被已有项淹没，从未改变最终选择——说明这块打分早已饱和，再加分只是噪声。
- **E5 同花拆法**：顺子优先的贪心在这套牌型规则下已经够用；同花拆法只在少数重叠局面改变估计，而这些局面里"为了凑同花拆掉对子"恰恰是错的。

**共同的教训**：这四条在直觉上都成立，在数据上都不成立。启发式打分的各项之间高度耦合、且有大量饱和项，靠"再补一条规则"很难拿到正收益。

## 五、顺手修掉的真 bug（F1）

`GameEngine.getOpponentCardCounts` 按座位号升序返回，而 `AIDecision` 用 `[0]` 当"下家"。只有 `myIndex = 0/3` 时恰好正确，`myIndex = 1/2` 时"报单保护"一直作用在错误的人身上——4 个座位里有 2 个的这条规则是失效的。

已改为从 `(myIndex + 1) % 4` 开始排列，sim 侧同样的错位一并修正。胜率上中性（17~18%，噪声内），但语义正确：**这类"看起来在生效、实际打错对象"的缺陷，比胜负数字更值得优先清掉**。

## 六、算力—胜率曲线：为什么说"别抠了"

| 0 号位配置 | 胜率（对 3×4.7 万节点大师） |
|---|---|
| 纯启发式（0 算力） | 18.0% |
| 1 万节点搜索（手机约 0.55s） | 18.0% |
| 2.5 万节点搜索（手机约 1.4s） | 21.0% |

**启发式用零算力打平了 1 万节点搜索；算力再翻 2.5 倍只换 3pp。** 这条曲线比任何单点改动都更能说明问题：这套 4 人牌局的胜负主要由发牌决定，策略侧的可优化空间被压得很薄。

于是有两个推论：

1. 任何规则层面的微调，收益都在 2~3pp 量级、且方向不定——**必须用同场对抗 + 大样本才能分辨，凭直觉改必然踩坑**（本轮 4 次全踩）。
2. 普通模式要真提升，只剩"也跑短搜索"一条路（把 2.5 万节点那档搬进来，代价每步约 1.5 秒），但这会模糊与大师模式的定位边界，需要产品层拍板，不在本轮范围。

## 七、结论与后续

1. **普通模式暂停调优**。现有启发式在"零算力"约束下已接近规则表达力的上限，继续加规则的期望收益为负。
2. **真正的提升点在大师模式**：评估函数对"对手报单 + 有牌权"几乎不敏感（只扣 600 分，而胜负是 100 万）、对手节点排序每个走法都 `applyMove + quickEval + undoMove`（不记节点但吃掉时间）。这两条都有明确机制支撑，且能直接用 `NODE_LIMIT_SEATS` 做同场验证。
3. 若哪天要动普通模式，先跑 `LEGACY_SEATS` 基准确认尺子没漂，再谈改动。

## 八、复现

```bash
# 基准：新版 vs 旧版快照，四家全启发式，400 局约 1 秒
HEURISTIC_SEATS=0,1,2,3 LEGACY_SEATS=1,3 ./sim/run-sim.sh 400 0 1 8 7

# 多 seed 扩大样本（判 1pp 级差异）
for s in 7 101 202; do
  HEURISTIC_SEATS=0,1,2,3 LEGACY_SEATS=1,3 ./sim/run-sim.sh 1200 0 1 4 $s
done

# 算力曲线：0 号位 1 万节点 vs 其余 4.7 万
SIM_NODES=47000 NODE_LIMIT_SEATS=0:10000 ./sim/run-sim.sh 100 0 0 8 7

# 外部校验：对 3 大师的胜率（钝刀，只做最终确认）
HEURISTIC_SEATS=0 HUMAN_MODEL_SEAT=0 HUMAN_MODEL_WEIGHT=0.8 \
  SIM_NODES=47000 ./sim/run-sim.sh 100 0 0 8 7
```

说明：

- `AIDecisionV0.kt` 是本轮开始前后的冻结快照，与当前 `AIDecision.kt` 的差异只在 object 名与注释（可用 `diff <(sed 's/AIDecisionV0/AIDecision/g' sim/AIDecisionV0.kt) app/src/main/java/com/chudad/game/logic/AIDecision.kt` 验证）。它的用途是**给未来的改动当基准**，不是历史包袱。
- 基准 49.3% 而非精确 50%，是因为"三项全关"那组仍包含 F1 的下家识别修复（-0.7pp，噪声内）。
- `run-sim.sh` 的 `nodeLimit` 传 0 即"不限"；纯启发式场景不进入搜索，该参数无影响。
