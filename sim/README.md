# sim —— 大师模式仿真与性能基准

纯 JVM 跑的离线工具，不依赖 Android SDK / Gradle。业务代码与 App 同源（直接编译 `app/src/main/java` 下的
`model/`、`CardRuleEngine`、`AIDecision`、`MasterSearch`、`PerfBench`），所以结论可以代表线上行为。

```
sim/
├── run-sim.sh          编译 + 运行（仿真 / 性能基准两种模式）
├── SimMain.kt          4 人对局仿真：胜率、回合数、非法走法、每步搜索量
├── PerfMain.kt         性能基准：与 App 内「设置 → 性能测试」同一份实现
├── AIDecisionV0.kt     普通模式旧版快照，仅供 LEGACY_SEATS 做 A/B，不进 APK
├── README.md           本文件：用法
├── MASTER-TUNING.md    大师模式调优复盘（JFR 热点、等价改写、座位偏差）
└── HEURISTIC-TUNING.md 普通模式调优复盘
```

## 一、快速开始

```bash
# 固定 12 万节点预算跑 100 局（推荐：A/B 对比用这个）
SIM_NODES=120000 ./sim/run-sim.sh 100 0 0 4 7

# 时间预算：每步 300ms（不传 nodeLimit ＝ 不限，与线上同档）
./sim/run-sim.sh 100 300 0 4 7

# 时间预算 + 显式节点兜底
./sim/run-sim.sh 100 300 500000 4 7

# 性能基准：与手机端同一份代码、同一批局面
./sim/run-sim.sh perf 300
```

参数依次为 `games deadlineMs nodeLimit threads baseSeed`；`nodeLimit` 传 `0` 或省略即不限
（与线上一致，时间才是唯一瓶颈），只有在需要固定节点预算时才显式给值。
设了 `SIM_NODES` 时，脚本会覆盖 `deadlineMs`/`nodeLimit` 两个位置参数，`games`/`threads`/`baseSeed` 仍按所给。

## 二、两种预算模式：什么时候用哪个

| | 时间预算 | 固定节点预算（`SIM_NODES`） |
|---|---|---|
| 停止条件 | `deadlineMs` 到点 | 节点数到上限 |
| 可复现性 | 同一 seed 两次跑可能不同决策 | **完全确定**（同 seed 同配置逐字节相同） |
| 受 CPU/负载影响 | 是（并行跑多组会互相拖慢、深度变浅） | 否（超订只拖时长，不改结果） |
| 每步耗时 | 恒定 | 随局型浮动 1.6 倍 |
| 贴近真机 | 是（真机就是时间受限） | 否（会把开局搜得比真机更深） |

实测（JIT 预热后）：同样 300ms，**开局与中局能搜到的节点数差约 1.6 倍**（走法生成成本不同：
能出同花/顺子的局面分支多）。时间预算买到的是**不等量的思考量**。

所以：

- **A/B 对比、调参 → 固定节点**（消除噪声，差异只剩策略本身）；
- **对齐真机表现 → 时间预算**（跑小样本交叉验证，确认固定节点得到的结论方向没变）。

> 沙箱 cgroup 只给 4 核。并行跑多组时时间预算会超订、每组实际深度不同，结果不可比；
> 固定节点无此问题，但仍建议 `threads` 不超过核数。

## 三、环境变量

| 变量 | 默认 | 含义 |
|---|---|---|
| `SIM_NODES` | 无 | 设了就走固定节点预算（自动把 deadline 放宽到 600s） |
| `HEURISTIC_SEATS` | 空（设了 `HUMAN_MODEL_SEAT` 时默认为该座位） | 哪些座位用普通模式 `AIDecision` 出牌，如 `0` 或 `0,2`；其余用大师搜索 |
| `HUMAN_MODEL_SEAT` | -1 | 把哪个座位当「人类」建模（-1 = 不建模，四家全大师） |
| `HUMAN_MODEL_WEIGHT` | 0.0 | 建模强度：1 = 完全信任代理走法，0~1 = 软建模，0 = 全量展开对照 |
| `OPP_MODEL` | `selfish` | 对手模型：`selfish`（各自最优，线上默认）或 `paranoid`（三家联盟 MIN） |
| `SELFISH_SEATS` | 全部 | 按座位指定谁用 selfish；设空集即全部退回 paranoid |
| `OPP_TOPK` | 2 | selfish 模型每个对手节点保留的候选数 |
| `MAX_DEPTH` | 自动 | 迭代加深上限；不设即按剩余牌数推导（= 线上，不会早于终局截断）。压到 8~12 可做「浅搜索」对照 |
| `LEGACY_SEATS` | 空 | 这些座位改用 `AIDecisionV0.kt` 旧版启发式（普通模式 A/B 用） |
| `LEGACY_EVAL_SEATS` | 空 | 这些座位用「旧评估」（不做对手报单终局化，大师模式 A/B 用） |
| `NODE_LIMIT_SEATS` | 空 | 按座位覆盖节点预算，如 `0:10000`（测「算力 → 胜率」曲线） |
| `JAVA_OPTS` | `-Xss32m -Xmx4g` | JVM 参数；容器里务必保留堆上限，否则默认 1/4 物理内存会被 cgroup OOM kill |

常用组合：

```bash
# 全大师基线（四家都大师）
HUMAN_MODEL_SEAT=-1 ./sim/run-sim.sh 100 ...

# 3 大师 vs 1 个普通模式代理，不开建模（= 测大师对外强度）
HEURISTIC_SEATS=0 HUMAN_MODEL_SEAT=0 HUMAN_MODEL_WEIGHT=0 ./sim/run-sim.sh 100 ...

# 线上配置：其余 3 座对 0 号座按 w=0.8 软建模
HEURISTIC_SEATS=0 HUMAN_MODEL_SEAT=0 HUMAN_MODEL_WEIGHT=0.8 ./sim/run-sim.sh 100 ...
```

## 四、性能基准与手机对齐

`./sim/run-sim.sh perf <budgetMs>` 与 App「设置 → 性能测试」跑的是**同一个 `PerfBench`**：
标准 52 张开局，把持 ♦3 的手牌换到 0 号位（口径固定为「0 号先出、首手含 ♦3」），
不建人类模型，对手模型取线上默认；预热 2 组丢弃后跑 10 组，记录每组的节点数 / 完整深度 / 耗时。

沙箱参考值（JVM 20，4 核配额，10 组）：

```
300ms : 平均 128,454 节点 / 25.5 层 / 428 节点每 ms
5000ms: 平均 3,185,143 节点 / 35.9 层 / 637 节点每 ms
```

两点解读上的注意：

- **组间离散度大（约 3 倍）是正常的**：不同开局的走法生成成本差很多（能出同花/顺局的分支多）。
  所以看**中位数**比看均值可靠；手机与沙箱逐行比对时，因为用的是同一批 seed、同一批局面，
  节点数完全相同，只有耗时不同，比值仍然成立。
- **不要跨预算档比速率**：`节点/ms` 不是纯算力常数。每次决策有固定开销（根走法枚举、排序、
  State 构造）不计入节点数，预算越短这部分占比越高。**对齐机型请用同一档预算做比值**，再按目标预算换节点。

### 真机标定（vivo V2227A / Android 16 / debug APK，2026-10-31）

| 手机预算 | 实测节点（均值） | 深度 | 手机速率 | 沙箱等效耗时 |
|---|---|---|---|---|
| 300ms | 3,363 | 14.0 层 | 11 节点/ms | ≈ 8ms |
| 3000ms | 46,779 | 22.1 层 | 16 节点/ms | ≈ 105ms |
| 5000ms | 87,659 | 24.2 层 | 18 节点/ms | ≈ 195ms |

**换算关系：手机 ≈ 沙箱的 1/25**（节点比 23.9× / 25.9×，速率比 24.4× / 25.2×）。两个实用映射：

- 沙箱 **300ms ≈ 手机 5s**；
- 沙箱 **150ms ≈ 手机 3s**（约 4.7 万节点）。

手机速率随预算上升（11 → 16 → 18 节点/ms）是 ART 冷启动未编译热点的表现，
估算较短档位时应用目标档附近的值，或取略低一档做保守估计。

> 这组标定是在 2026-10-31 的版本上测的（debug 包）。当前版本同预算能搜到的节点数约多 45%，
> 重测之前请按上表做**保守**估计：实际只会更多，不会更少。

标定公式（换设备 / 换包型就重测一遍）：

```
手机算力比   = 手机速率 ÷ 沙箱速率（同为 300ms 档）
等价节点预算 = 手机预算(ms) × 手机速率(节点/ms)
```

先算出「手机在目标预算下能搜多少节点」，再用 `SIM_NODES=<该值>` 跑仿真，结论才与真机同档。

## 五、结果怎么读

```
=== 结果 ===
玩家0 胜率: 12/50 (24.0% ±12.0)      ← ±X 是 95% 置信区间
平均回合数: 61.2  (完成局数 50/50, 异常 0)
搜索量: 平均每步 118000 节点 / 24.3 层（最深 33 层，步数 3050，预算 固定节点 120000节点）
非法走法次数: 0
总耗时: 212000ms  (worker=4)
```

- **公平值 25%**：四家牌力均等，某座位显著偏离 25% 说明该配置有系统性优势/劣势。
  注意 100 局的 95%CI 约 ±8.5pp，**单 seed 100 局分不出 5pp 以内的差异**，坐实到 ±4pp 需 400 局，并换 seed 复跑确认方向一致。
- **非法走法必须为 0**：非 0 说明搜索输出了不合规则的牌，脚本会用最小合法走法继续推进并打印样本。
- **搜索量**：固定节点模式下 `平均每步` 会略低于上限（部分局面提前算出必胜/必败而结束）；
  时间预算模式下它反映「这个档位实际花了多少预算」，可用来核对是否与预期档位一致。
- **异常**：应恒为 0。非 0 说明有局抛异常（通常是被预算/栈配置拖崩）。

## 六、A/B 对照工具

对 3 个大师跑「启发式胜率」是钝刀（100 局 ±8.5pp，天花板只有 18pp），改 2~3pp 根本测不出来。
sim 内置三个开关，直接做**同场对抗**（基准点 50%，量程最大）：

| 变量 | 用法 | 判据 |
|---|---|---|
| `LEGACY_SEATS=1,3` | 这些座位跑 `AIDecisionV0.kt` 旧版快照，其余跑当前 `AIDecision` | 四家全启发式、新版坐 0/2：新版两座合计 >50% 才算变强 |
| `LEGACY_EVAL_SEATS=1,3` | 这些座位用旧评估（不做对手报单终局化） | 四家全大师：新评估两座合计 >50% 才算变强 |
| `NODE_LIMIT_SEATS=0:10000` | 按座位覆盖节点预算 | 同源不同算力对打，测「算力 → 胜率」曲线 |

```bash
# 普通模式新旧对抗（启发式不搜索，400 局约 1 秒）
HEURISTIC_SEATS=0,1,2,3 LEGACY_SEATS=1,3 ./sim/run-sim.sh 400 0 1 8 7

# 大师评估对抗：必须对调座位跑两轮再合并，单轮结果会被座位偏差带偏
LEGACY_EVAL_SEATS=1,3 SIM_NODES=47000 ./sim/run-sim.sh 400 0 0 4 7
LEGACY_EVAL_SEATS=0,2 SIM_NODES=47000 ./sim/run-sim.sh 400 0 0 4 7

# 算力曲线：0 号位 1 万节点 vs 其余 4.7 万节点
SIM_NODES=47000 NODE_LIMIT_SEATS=0:10000 ./sim/run-sim.sh 100 0 0 8 7
```

**判定纪律**（都是在实践里踩出来的）：

- **必须对调座位跑两轮再合并**。四家全大师时 0/2 座天然比 1/3 高约 4.5pp（≈4σ，来源未定位），
  单轮 A/B 会被它直接带偏。
- 400 局的 95%CI 约 ±3.5pp，**只能判「有没有 >3.5pp 的变化」**；要判 1pp 级需 3 个 seed × 1200 局。
- 只有"方向一致 + 幅度超噪声"才算提升；单纯一次正向不上线。
