# 大师模式（搜索）调优复盘

> 时间：2026-11-01　对象：`MasterSearch.kt`、`CardRuleEngine.kt`（4 人完美信息 alpha-beta 搜索）
> 结论先说：**固定节点预算下棋力没有可测提升（+3.2pp，1.1σ，噪声内），这不是失败——是等价改写的必然结果。真正的产出是把搜索速度提了 45%，在"时间受限"的线上直接兑换成"同样的秒数搜得更深"；另外挖出两个比棋力更值钱的东西：一个让所有仿真结论不可复现的缓存 bug，和 4.5pp 的座位偏差。**

## 一、定位与基线

线上大师模式是**时间受限**的：层数上限按剩余牌数自适应（撞上时必然已算到终局），节点阀 600 万只是安全阀。也就是说，"最大思考时间"是唯一能调强弱的旋钮，**唯一确定有效的优化方向是"单位时间搜得更深"**，而不是继续堆评估权重。

基线口径（3 大师 + 1 启发式，大师开 `w=0.8` 人类建模与 selfish，固定 4.7 万节点 ≈ 手机 3s，seed=7，400 局）：

| 版本 | 启发式胜率 |
|---|---|
| 优化前 | 18.8% ±4.2 |
| 优化后 | 22.0% ±4.2 |

差 3.2pp、1.1σ —— **落在噪声里**。这个数字本身在第三节就能解释：三处改动都是等价改写，不改变搜索内容，自然不改变棋力。

标尺问题与普通模式那次相同：400 局对大师的 95%CI 是 ±4.2pp，而候选改进的量级是 2~3pp。所以本轮不靠"对大师胜率"做判定，而是靠两条更硬的路：

- **等价性可证明**：改写前后输出必须逐字节一致（能用随机用例或整局对比验证）；
- **同场对抗 + 对调座位**：`LEGACY_EVAL_SEATS` 让新旧评估在同一张桌子上对打，基准点 50%，且必须两轮对调座位合并（原因见第七节）。

## 二、先测再改：JFR 采样定位热点

不做猜测，直接用 JFR 采样：`-XX:StartFlightRecording`，固定 4.7 万节点跑 2 局，得 892 个样本，按栈中出现过的方法统计：

| 栈中出现过的方法 | 占样本 | 说明 |
|---|---|---|
| `generateMoves` | 20.1% | 走法生成，正常开销，未动 |
| `evaluate` | 14.2% | 其中 `handStrength`→`hasStraightFlush` 占 8.6%：**每个叶节点对 4 家手牌各扫一遍花色** |
| `orderBySelfInterest` | 11.5% | 对**每个候选走法**都重算 3 家 `minPlays` + 一轮 `applyMove/undoMove` |
| `findAllValidPlays`（仅判非空） | 8.0% | 只为一个布尔值就枚举全部候选（含所有五张牌型） |
| `TransKey.equals` | 6.1% | 置换表 key 比较，TT 的固有成本，未动 |

结论很明确：**棋力相关的评估逻辑只占 14%，而"为一两个布尔值付出的重复计算"占了近 20%**。这三处不需要任何策略判断，改了就是白赚。

## 三、方向一：三处等价改写（唯一确定的收益）

| 改动 | 做法 | 等价性证据 |
|---|---|---|
| 新增 `CardRuleEngine.canBeat` | "当前出牌方能否压 top"改成存在性判定：单/对/三条用「点数 → 花色位掩码」直接比；五张牌型仍走生成器但命中即返回 | 90 万随机用例（含 30 万跟牌、覆盖全部五张牌型）与 `findAllValidPlays(..).isNotEmpty()` **零不一致** |
| `hasStraightFlush` 改位运算 | 4 个花色各维护一个 16 位点数掩码，窗口用与运算判断，替代原来每花色 `filter/toSet` 生成新列表 | 20 万随机手牌与旧实现**零不一致** |
| `orderBySelfInterest` 提公共项 | 其余三家的「手数 / 张数」与"本手出什么"无关，提到循环外只算一次 | 100 局固定节点：**胜负 / 步数 / 节点数与改前完全相同** |

效果（同环境、同代码路径，`run-sim.sh perf`，10 组）：

| 预算 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 300ms | 87,562 节点 / 24.1 层 / 292 节点每 ms | 128,454 / 25.5 层 / 428 | **+47% 节点，+1.4 层** |
| 5000ms | 2,194,564 / 34.8 层 / 439 | 3,185,143 / 35.9 层 / 637 | **+45% 节点，+1.1 层** |

线上是时间受限，所以这 45% 直接等于"同样的秒数里深 1~1.5 层"。**在固定节点口径下它体现为 0 棋力提升，这是正常的、也是必须接受的**——否则说明改写不等价，那才是问题。

## 四、方向二：评估补"对手报单终局化"（+1.2pp，噪声内）

`evaluate` 里"对手只剩 1 手"原本只体现为 `(oppPlays - myPlays) * 600` 的差额（几十到几千分），而 `WIN` 是 100 万。于是在深度边界上经常出现"下家已报单、却按均势估值"，alpha-beta 没有理由去拦。

补丁很窄，且条件与搜索自己判终局的口径**同源**（`applyMove` 后发现手牌空即 winner）：

```kotlin
// 轮到他、他又能出 → 他这一手就出完
if (cur != myIndex && hands[cur].size == 1 && (top == null || canBeat(hands[cur], top)))
    return -(WIN - 1)
```

同场对抗（四家全大师、固定 4.7 万节点、400 局 ×2、**对调座位**）：

| 轮次 | 新评估座位 | 新评估 | 旧评估 | 差 |
|---|---|---|---|---|
| 1 | 0/2 | 27.9% | 22.1% | +5.8pp |
| 2 | 1/3 | 23.4% | 26.6% | −3.2pp |
| 合并（1600 个座位-局观测） | — | **25.6%** | **24.4%** | **+1.2pp（0.96σ）** |

**单轮看起来像大胜，对调后直接反向**——这 5.8pp 主要是座位偏差（第七节），不是评估优劣。合并后只有 +1.2pp，噪声内。

保留这条补丁的理由是**逻辑无条件正确**（与搜索判终局同源），不是"实测变强了"。这一点必须写清楚，否则下一轮会有人拿它当前后对比的基线。

## 五、方向三：被回退的激进改写（负结果）

`orderBySelfInterest` 还有一版更彻底的重写：完全不调 `applyMove/undoMove`，直接用手牌过滤 + 手数差自己算"这手出完后的局面值"。

看着完全等价，跑起来**不等价**：100 局固定节点，胜负 / 步数 / 节点数与基线不同。
推测原因是 `quickEval` 还看了被 `applyMove` 改写的其它字段（当前出牌方、桌面牌型、过牌数），
而"只算手牌"复现不了那部分——这层未逐项验证，但"输出不同即不等价"这个判定与原因无关。

已回退，只保留"把 3 家 `minPlays` 提到循环外"这条严格等价的改动。

**教训**：性能改写必须先证明等价（整局逐字段对比，或大样本随机用例），否则你测到的是"策略变了"，不是"变快了"；而策略变化在 400 局 ±4pp 的尺子上根本分不清。

## 六、副产品：修掉让仿真不可复现的 bug

这轮排查"为什么改前改后结果对不上"时发现：**固定节点模式下，同一 seed 跑两次结果本来就不一样。**

根因：

- `minPlays` 的贪心拆牌结果**依赖手牌列表顺序**（顺子窗口的选择顺序），而它的缓存键是**集合掩码**（不含顺序）；
- 缓存在 2 万条时整体清空，而清空时机在多线程下由调度决定；
- 于是同一局面可能命中"按 A 顺序拆出来的值"或"按 B 顺序拆出来的值"，胜负随之漂移（实测 20 局里就能差 1 局）。

修复：`minPlays` 入口先对牌排序再拆，使其成为纯函数（同掩码 ⇒ 同结果）。验证：100 局 ×2 次跑，胜负 / 步数 / 节点数完全一致。

> 这条比棋力重要得多。**在修它之前，所有"A 比 B 强 x pp"的结论都建立在不稳的地基上**，包括上一轮普通模式的四个负结果——那些结论方向大概率仍成立（四项一致偏负），但幅度不可信。

## 七、必须知道的发现：座位偏差 4.5pp

把上面两轮 A/B 的 800 局合起来（与评估版本无关，只按座位统计）：

| 座位 | 胜率 |
|---|---|
| 0 / 2 | 27.3% |
| 1 / 3 | 22.8% |

1600 个座位-局观测、标准误约 ±1.1pp，**4.5pp 的差距 ≈ 4σ**，不是噪声。发牌是对称的，先手由 ♦3 持有者决定也是对称的，**偏差来源尚未定位**（怀疑在流程性规则或搜索对座位索引的某处隐含假设）。

后果很直接：**任何单轮 A/B 都会被它带偏**——把新版本放在 0/2 会凭空多 4~5pp，放在 1/3 会凭空少 4~5pp。第四节那个"+5.8pp 然后 −3.2pp"就是活生生的例子。

纪律：

1. A/B 必须**对调座位跑两轮再合并**，单轮数字一律不看；
2. 或者用"双方各占两座、每座轮流当新版"的对称设计（本轮的 400 局 ×2 就是）；
3. 在偏差定位之前，**任何 <4pp 的结论都不值得当成"提升"**，最多记为"方向一致"。

## 八、结论与后续

1. **棋力**：固定节点下无可测提升（+3.2pp / 1.1σ），符合"等价改写"的预期；评估补丁 +1.2pp 同样在噪声内，保留仅因逻辑正确。
2. **成本**：搜索快 45%（300ms 从 87.6k → 128.5k 节点，5s 从 219 万 → 319 万），线上兑现为同秒数深 1.1~1.4 层。这是本轮唯一的确定收益。
3. **正确性**：修掉 `minPlays` 缓存导致的非确定性；从此"固定节点 + 同 seed = 逐字节相同"才真正成立。
4. **下一步优先级**（按投入产出排序）：
   - **先查座位偏差**。它现在会污染每一个 A/B，是所有后续实验的地基。
   - `aspiration window`（每层用上一层的值开窄窗口）与 TT 容量上限（现在是无上限 HashMap，深层几十万条，GC 压力）。
   - 评估权重网格（`W_PLAYS / W_CARDS / W_CTRL / LEAD / SEIZE`）与 `OPP_TOPK`——但这三项都属"策略微调"，预期 2~3pp 量级，**必须等偏差查清、尺子校准后再做**。
5. **方法论**：这一轮真正的收获不是 45%，而是三件事——先 JFR 再动手、等价改写必须能证明、A/B 必须对调座位。这两轮（普通模式四次、本轮一次）"直觉上成立"的改动全被数据否掉，说明这套牌局的策略空间已经非常平。
